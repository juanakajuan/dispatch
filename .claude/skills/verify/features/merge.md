# Merge

A user presses `m` twice to merge a PR. The first press says what dispatch expects to do. The second press reads the PR from GitHub again, then merges a clean PR with `gh pr merge`, sends a fix prompt to the running session of a PR with a problem, or starts a new session to fix it. After a direct merge, dispatch stops the session on the PR's branch, live or exited.

## Sub-features

- `merge-arm` shows the expectation on the first `m`, for example `Press m again to merge PR #P`.
- `merge-cancel` disarms when any other key comes before the second `m`. The arm has no timeout. Only the toast goes after 5 s.
- `merge-rearm` asks once more when the fresh read changes the plan. If the first press expected a merge or an agent but the second press finds a problem with no live session, the second `m` shows `PR #P has … Press m again to start a session for #N that fixes it.`, and a third `m` starts it.
- `merge-direct` runs `gh pr merge <P> --<method> --match-head-commit <sha>` for a PR whose merge state is `CLEAN` or `HAS_HOOKS`. The toast is `Merged PR #P (<method>)`. If the PR reads back as merged (or the read fails), it also stops the session on that branch. A running or needs-you session gives `Merged PR #P (<method>) and stopped #N's session`. An exited session gives `Merged PR #P (<method>) and closed #N's window`, so a terminal or herdr app space that outlived Claude is closed too. If the PR is still open, the toast is `PR #P is in the merge queue`.
- `merge-handoff` sends the live session on the PR branch a prompt that names the problem and the merge command. The second press shows `<problem> Asking #N's agent to fix it.`, then `Asked #N's agent to fix and merge its PR`.
- `merge-new-session` starts a session to fix a PR that has a problem (failing checks, conflict, behind, blocked by a rule, unstable) and no live session. It goes to the Sessions tab. An exited session on the PR branch gives a new session for the same issue. Otherwise the session is for the first issue that the PR closes and that has no session. If the PR closes no issue: `PR #P closes no issue, so dispatch can not start a session for it.` If each closed issue has a session on another branch: `Each issue that PR #P closes already has a session on another branch.`
- `merge-fork` starts the same fix session for a PR from a fork, on the local branch `fork/pr-P`. Only a PR that allows edits from maintainers gets one. The start adds the fork as the git remote `dispatch-fork-pr-P`, whose fetch and push refspecs map only the PR's branch to `fork/pr-P`, and fetches it. So `git pull` and a plain `git push` reach the PR. The fix prompt never names the fork's branch, because the fork's author chose it. Remove (`D`) deletes the remote too. A PR that does not allow edits from maintainers gets, on the first `m`, `PR #P has … PR #P is from a fork that does not let maintainers push to it, so a session can not push a fix.` A clean fork PR still merges directly.
- `merge-ready` handles a draft. The first `m` shows `PR #P is a draft. Press m again to mark it ready and merge it.` The second `m` runs `gh pr ready <P>`, reads the PR again, and plans from that. If the merge does not follow, the toast adds ` PR #P is now ready for review.`, because dispatch does not undo `gh pr ready`.
- `merge-refuse` says why when checks run, the PR is not open, or GitHub has not decided. Other refusals: `PR #P is blocked and has no checks yet. If checks are about to start, press m again soon. If it needs a review, get one first.` and `PR #P is still a draft.` A refusal that only the fresh read finds still arms on the first press with `Press m again to merge PR #P`. A PR that became a draft after the first `m` shows `PR #P is a draft now. Press m twice again to mark it ready and merge it.`
- `merge-method` reads `git config dispatch.mergeMethod`, else the first method the repo allows. A method the repo does not allow gives `dispatch.mergeMethod is X, but the repo allows only: …`.

## How to get to it (user POV)

- On the Pull requests tab, select an open PR and press `m` twice.
- On the Issues tab, select an issue that has a PR and press `m` twice. The issue uses the PR of its session, else its lead PR (merged before open before draft). An issue with a merged PR and an open PR gives `PR #<merged> is not open.`
- On the Sessions tab, select a session that has a PR and press `m` twice.
- The key bar shows `m to merge` only when the selected row has an open or draft PR. The `?` menu lists `m` under `Pull requests`.

## Driving it with verify.sh

Preconditions:

- A run is up without `--allow-merge`, and doctor shows no `FAIL`. The guard blocks `gh pr merge`, so no PR merges.
- The Pull requests tab lists an open PR `#P` (`PR #P open` on its row), and the key bar shows `m to merge`. Pick repos with the check command in [README.md](README.md). One repo seldom has both a `CLEAN` PR and a PR with a problem that closes an issue, so the direct merge can need a second run on another repo.

- **Arm.** Press `2`, select `#P`, press `m`. Run `$V keys "$RUN" 2`, move with `j`/`k`, then `$V keys "$RUN" m`. The message row shows `Press m again to merge PR #P`, or a problem sentence such as `PR #P has failing checks. Press m again to start a session for #N that fixes it.` The first press reads only the cached list: `gh-calls.log` gets no `gh pr view P`. Run `$V shot "$RUN" merge-armed`.
- **Cancel.** Press `j` then `k`, then `m` once. The message row shows the first-press text again, not `Checking PR #P`. dispatch is now armed again.
- **Direct merge (`CLEAN` PR).** After **Cancel**, press `m` one time (else press it twice). Run `$V keys "$RUN" m` and `$V wait "$RUN" 'blocked by dispatch verify guard' 15`. The message row shows `Checking PR #P`, then `Merge PR #P failed: gh failed with code 1: blocked by dispatch verify guard: gh pr merge P --<method> --match-head-commit <sha>`. `$RUN/evidence/gh-blocked.log` has `BLOCKED <time> gh pr merge P --<method> --match-head-commit <sha>`. `gh-calls.log` shows `gh pr view P` and `gh repo view` before it. Run `$V shot "$RUN" merge-blocked` at once.
- **New session (PR with a problem, no session).** Select a PR whose row shows a problem such as `✗ checks failing`, and that closes an issue `#N`. Press `m`. The message row says `PR #P has … Press m again to start a session for #N that fixes it.` Press `m` again. The message row shows `Checking PR #P`, then `PR #P has … Starting a session for #N to fix it.` dispatch goes to the Sessions tab and starts a session for `#N` on the PR branch. `$V state` shows the worktree `.claude/worktrees/N` on the PR head branch and the marker. The argv in `claude-calls.log` has `This worktree is on the branch of PR #P. Run \`gh pr checkout P\` …`.
- **Fork new session (fork PR with a problem that allows maintainer edits).** Select a fork PR (`fork=true edits=true` in the README check command) that has a problem and closes an issue `#N`. Press `m` twice, as in **New session**. `$V state` shows the worktree `.claude/worktrees/N` on the branch `fork/pr-P`. In the clone, `git config --get-regexp 'dispatch-fork-pr-P|branch\.fork/'` shows the fork's URL with the host and protocol of `origin`, the push refspec `refs/heads/fork/pr-P:refs/heads/<head>`, and `branch.fork/pr-P.merge refs/heads/<head>`. The session row shows `✓` (pushed), not `↑N`. The argv in `claude-calls.log` has `This worktree is on the branch of PR #P, from the fork <owner>/<name>. Run \`git pull\` to get its latest commits. A plain \`git push\` pushes to the PR.`
- **Fork refusal (fork PR with a problem that does not allow maintainer edits).** Select a fork PR with `edits=false` that has a problem. Press `m`. The message row shows `PR #P has … PR #P is from a fork that does not let maintainers push to it, so a session can not push a fix.` A second `m` arms nothing and starts nothing.
- **Handoff (PR with a problem, live session).** Stay on the Sessions tab with `#N` selected, or select `#P` on the PR tab. Press `m`. The message row shows `Press m again to ask #N's agent to fix and merge it.` Press `m` again and `$V wait "$RUN" "Asked #N's agent to fix and merge its PR"`. `claude-calls.log` has `got: PR #P has … When the checks pass, merge it with \`gh pr merge P --<method>\`.`, and `$V window "$RUN" '#N'` shows `FAKE-CLAUDE got: PR #P …`.
- **Not open.** Select a merged PR. The key bar has no `m to merge`. Press `m`. The message row shows `PR #P is not open.`

## Gotchas

- Never use `--allow-merge` on a repo whose PRs matter. With it, a clean PR really merges.
- The guard turns a direct merge into an error toast. dispatch then does not stop the session, so `merge-direct`'s session stop is not proven by this recipe. It needs a sandbox repo and `--allow-merge`.
- A PR can merge or close on GitHub during the run. The first press reads the cached list, so it can still arm. The second press reads the PR again and shows `PR #P is already merged.` or `PR #P is closed.` Press `r`, wait for `updated`, and pick a PR again.
- A direct merge needs merge state `CLEAN`. On a repo that requires a review, an open PR with passing checks is `BLOCKED`, and `m` hands it off with `PR #P is blocked by a branch rule, such as a required review.` instead.
- The new-session fix needs a PR that closes an issue. A fork PR also needs `maintainerCanModify`, which the PR's author sets. A fork that is gone reads as no edits allowed.
- The fork start fetches from the fork itself, not from `origin`. A fork that is private or gone makes the start fail with a git error toast.
- The guard blocks `gh pr ready`. On a draft, the second `m` shows a `Merge PR #P failed:` toast that contains `blocked by dispatch verify guard`, and `gh-blocked.log` gets `gh pr ready P`. The guard has no flag that lets `gh pr ready` through.
- The new-session fix runs `git fetch origin <head>` and then `git worktree add … origin/<head>`. This needs a clone that tracks every branch. `up` sets this, and doctor checks it. If the start fails with `invalid reference: origin/<head>`, the clone tracks only the default branch.
- The merge method comes from `git config dispatch.mergeMethod` in the run's clone, not in the user's checkout.
