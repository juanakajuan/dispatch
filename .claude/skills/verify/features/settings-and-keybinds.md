# Settings and keys

A user presses `,` to open the settings menu and `?` to open the keys menu. The settings menu changes `detect_waiting`, `icons`, `multiplexer`, `harness`, `command`, and `remove_on_merge`, and saves the changes to `config.json` when you press Enter. The keys menu lists every key binding by group. The key bar on the last line shows only the keys that work on the selected row.

## Sub-features

- `keys-bar` shows `<key> to <action>` pairs joined by ` · `, only for actions that work on the selected row, with one hint per action. `? to show keys` is always first and `q to quit` last. An empty tab shows only `? to show keys · q to quit`. A key is written as the keys menu writes it (`ctrl+s`, `down/up`). `enter to go to issue` shows only on a PR that closes an issue. `space to mark` shows only on an issue with no session. On an issue or PR row that has a session, `s` goes to it, so the bar shows `s to go to session` instead of `s to start session`, and the prompt shows `s to go to session`. `d to show diff` shows only when the session has changes. `m to merge` shows only for a row with an open or draft PR, `x to stop` and `t to send message` only for a live session, and `a to resume` only for an exited one. The prompt placeholder follows the same rule.
- `keys-menu` (`?`) shows a box titled ` Keys ` with the groups `Navigation`, `Sessions`, `Pull requests`, `View`, `App`, one row per binding, for example `j/down    move down`. `j`/`k` scroll. Every other key is swallowed, so `q` does not quit. `Esc` or `?` closes it.
- `settings-menu` (`,`) shows a box titled ` Settings ` with one row per setting: `<key>  < <value> >   default: <default>`. A value that `h`/`l` change has `< ` and ` >` around it; the `command` value has none. The selected row starts with `›`. A note under the rows says when the change applies. Under it, a hint says `Press ←/→ to change the value.`, or `Press enter to edit the command.` on the `command` row. The last line is `Changes save to config.json when you press enter.`, or `Not saved. Press enter to save to config.json.` when a value is changed and not saved. The key bar is `j/k to move · h/l to change · enter to save · esc to cancel`, and on the `command` row `j/k to move · enter to edit · esc to cancel`.
- `settings-change`: `Right`/`l` selects the next value and `Left`/`h` the previous one, for `detect_waiting` (on, off), `icons` (unicode, nerdfont), `remove_on_merge` (off, on), `multiplexer` (`auto`, `tmux`, `herdr`, `herdr-app`), and `harness` (`claude`, `codex`, `opencode`, `antigravity`, `pi`). An on/off setting toggles with both keys. The keys do not save. A new `harness` shows the `command` it gives (its program). Back on the saved harness, the saved `command` comes back. The arrows do not change `command`.
- `settings-close`: Enter saves every changed setting to `config.json` in one write and closes the menu. `Esc` or `,` closes it and drops the changes. A new menu starts from the saved values.
- `settings-edit` opens an inline editor for `command` on Enter. It shows the command that runs now (the harness program when there is no override). Enter checks the text, then saves all changes and closes the menu. Esc cancels the edit and keeps the menu open. Words split on spaces, and quotes group them. The editor edits as the filter does (see `lists-filter` in lists.md), and the row shows the mark `▏` at the cursor: clear it with `C-j`, type `claude --model opus`, press Home, type `A`, press Left twice, type `B`, and the row shows `command +B▏Aclaude --model opus`. A command wider than the row shows the part around the cursor: the tail with the cursor at the end, and `X▏claude …` after Home and `X`.
- `keys-mouse`: a click on a key bar entry or on `S sort: <order>` presses that key. A key cut at a narrow width is not clickable. Each menu box has `esc ✕` in its top border, which closes it. A click on a settings row selects it, and a second click selects its next value as `l` does (on `command` it opens the editor). A click never saves. A click on a keys menu entry closes the menu and runs that binding. The wheel moves through the settings and scrolls the keys menu.
- `settings-save` writes `$XDG_CONFIG_HOME/dispatch/config.json`. It changes only the keys of the changed settings, keeps the other keys, and removes a key when the value is the default. A success shows no toast. A failure shows `Saving settings failed: <error>.`.

## How to get to it (user POV)

- Press `?` from any tab. The key bar always shows `? to show keys`.
- Press `,` from any tab. The key bar does not show `,`. The keys menu lists it under `App`.

## Driving it with verify.sh

Preconditions:

- A run is up and doctor shows no `FAIL`. Set `CFG=$RUN/xdg/dispatch/config.json` and save `jq -c . "$CFG"`. It has `command` and `"multiplexer":"tmux"`.

- **Key bar.** Press `3` with no sessions: the bar shows only `? to show keys · q to quit` and the prompt shows `/ to filter sessions`. Press `1`. Run `$V wait "$RUN" '\? to show keys · s to start session'`. The bar ends with `q to quit`. Press `3` with a live session selected: the bar has `a to attach · x to stop · t to send message` (no `enter`), and the prompt shows `/ to filter sessions · a to attach`. Run `$V shot "$RUN" keybar`.
- **Keys menu.** Press `?`. Run `$V keys "$RUN" '?'` and `$V wait "$RUN" ' Keys '`. The screen shows `Navigation`, `Pull requests`, `j/down +move down`, `q/ctrl\+c +quit`, `, +open the settings menu`, and the key bar `j/k to scroll · esc to close`. Run `$V shot "$RUN" keybinds`. Press `q`: the menu stays open. Press `Escape`: ` Keys ` is gone. Open it again with `?` and close it with `?`.
- **Settings menu.** Press `,`. Run `$V keys "$RUN" ,` and `$V wait "$RUN" ' Settings '`. The rows are `› detect_waiting   < on >   default: on`, `icons            < unicode >   default: unicode`, `multiplexer      < tmux >   default: auto`, `harness          < claude >   default: claude`, `command          $RUN/bin/fake-claude…   default: claude`, and `remove_on_merge  < off >   default: off`. Names are padded to one width, so match with ` +` between the words, for example `$V wait "$RUN" 'icons +< unicode > +default: unicode'` and `$V wait "$RUN" 'remove_on_merge +< off > +default: off'`. The note is `Applies to sessions you start or resume after this change.`, and the hint under it is `Press ←/→ to change the value.` The box ends with `Changes save to config.json when you press enter.`, and has no key hints: the key bar is `j/k to move · h/l to change · enter to save · esc to cancel`, and the prompt line has no hint. Run `$V shot "$RUN" settings`.
- **Change without a save.** Press `Right`. `$V wait "$RUN" 'detect_waiting +< off >'` and `$V wait "$RUN" 'Not saved. Press enter'`. Press `Left`: `detect_waiting +< on >`, and the note is `Changes save to config.json when you press enter.` again. Press `l`, then `h`. Wait 0.5 s: `$CFG` is the same as the saved copy.
- **Enter saves all and closes.** Press `j`, wait for `› icons`, press `Right`: `icons +< nerdfont >`. Press `j` four times, wait for `› remove_on_merge`, press `l`: `remove_on_merge +< on >`. `$CFG` has not changed. Run `$V shot "$RUN" pending`. Press Enter. `$V wait "$RUN" '\? to show keys'`: the menu is closed. Poll the file with a bounded loop: `for i in $(seq 50); do jq -e '.icons == "nerdfont" and .remove_on_merge == true' "$CFG" && break; sleep 0.1; done`. `command` and `multiplexer` stay. The header line 6 has Nerd Font glyphs, not `▲`.
- **Esc drops the changes.** Press `,`: `icons +< nerdfont >`. Press `j` then `h`: `icons +< unicode >`. Press `Escape`. The menu is closed and `.icons` is still `nerdfont` in the file. Press `,` again: `icons +< nerdfont >`.
- **Back to the start.** In the open menu, press `j h`, then `j` four times and `l`: `icons +< unicode >`, `remove_on_merge +< off >`. Press Enter. Poll until `jq 'has("icons") or has("remove_on_merge")' "$CFG"` prints `false`.
- **Multiplexer.** Open the menu and select `multiplexer`. The note is `Applies the next time you start dispatch.` Press `Left`: `multiplexer +< auto >`. Press `Right` four times and wait for `< tmux >`, then `< herdr >`, then `< herdr-app >`, then `< auto >`. Press `Left` three times (`< herdr-app >`, `< herdr >`, `< tmux >`) to come back to `tmux`, and press `Escape`. The file keeps `"multiplexer":"tmux"`.
- **Harness.** Open the menu and select `harness` (three `j`). Press `l`. `$V wait "$RUN" 'harness +< codex >'` and `command +codex`. Press `h`: `harness +< claude >`, and the `command` row shows `$RUN/bin/fake-claude…` again. Press `h` again: the cycle wraps to `harness +< pi >` and `command +pi`. Press `Escape`. Do not save a new harness here: it clears `command`.
- **Editor error.** Open the menu and select `command`. The key bar is `j/k to move · enter to edit · esc to cancel`, the hint is `Press enter to edit the command.`, and `Right` changes nothing. Press Enter. `$V wait "$RUN" 'enter to save · esc to cancel'`. Run `$V type "$RUN" " 'oops"` and press Enter. `$V wait "$RUN" 'has a quote that never closes'`. The file does not change. Press `Escape` to cancel the edit. The menu stays open with the key bar `j/k to move · enter to edit · esc to cancel`. Press `Escape` to close it.

## Gotchas

- The save is asynchronous and silent. Prove it with a bounded poll on `$CFG`, not with a screen wait.
- Wait for `› <setting>` before you press `Left` or `Right`. If a wait times out, stop: the keys after it go to the list, not the menu.
- Do not save a changed `command`, or the run loses the fake claude. Saving a new `harness` also clears `command`, so do it only in a run that you drop after (the `harness` journey in sessions.md does). Cancel the editor with `Escape`.
- Do not leave `multiplexer` on anything but `tmux`. It applies at the next start, so a `restart` would start sessions in herdr or the herdr app, outside the sandbox.
- The `command` value is cut with `…`. Match `default: claude`, not the full path.
- The `icons` setting changes the glyphs in every other feature file. Set it back to `unicode` before you drive them.
- `github_refresh` is fixed at 60 s. The menu does not show it.
