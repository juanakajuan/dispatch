# Issue and PR lists

dispatch shows three tabs: Issues, Pull requests, and Sessions. Each tab is a list of rows in groups. dispatch fetches issues and PRs every 60 s, on `r`, and 5 s after events that change GitHub data. The header shows how old the data is. A user can filter and sort the rows.

## Sub-features

- `lists-tabs` switches tabs with `1` `2` `3` or a click, and shows the item count of each tab after its name, for example ` 2  Pull requests 10`.
- `lists-groups` puts rows in groups with a heading and a count. Issues: `Needs you`, `Working`, `In review`, `Merged`, `Open`. PRs: `Ready for review`, `Draft`, `Merged`, `Closed`. Sessions: `Needs you`, `Working`, `Exited`, `Merged` (a session whose PR merged, with a purple `✓`). An empty group is not shown.
- `lists-freshness` shows `loading…`, `updated Ns ago`, `refreshing…`, or `refresh failed Ns ago` after `<repo> · ` on header line 5, on tabs 1 and 2 only.
- `lists-refresh` fetches now on `r`.
- `lists-filter` keeps the rows that match the `/` text, without case. Issues match on number, title, and labels. PRs match on number, title, and head branch. Sessions match on number, issue title, and branch. The filter can also hold terms, mixed with free text: `label:bug`, `assignee:octo`, `assignee:@me`, `author:octo`, `author:@me`, `milestone:v1`, `state:<word>`, `checks:pass|fail|pending|none`, `has:pr`, `has:session`, `is:fork`, and `is:marked`. `state:` words are `open`, `draft`, `merged`, `closed`, `needs-you`, `working`, `exited`, and `in-review`. A term matches its field exactly, without case, and a value with spaces goes in double quotes (`milestone:"hyperfine 2.1"`). A `-` before a term key (`-label:wontfix`, `-has:pr`) keeps the rows that the term does not match. A row shows only when the text and every term match. On the Sessions tab, terms read the session's issue. On the Issues tab, `checks:` and `is:fork` read the lead PR. `@me` is the login from `gh api graphql -f query=query{viewer{login}}`, fetched once at start. The prompt shows each term (with its `-`) in the accent colour, a key with no value yet (`label:`) dim, a value outside the fixed words (`state:bogus`) red, and `@me` red if the login fetch failed. Tab in the filter input completes a term key or a value from the items of the tab, Tab again goes to the next choice, Shift-Tab to the previous one, and any other key ends it. Completion makes no `gh` call. Enter keeps the filter. Esc clears it, in the filter input and also from the list. Each tab keeps its own filter: a filter on one tab does not change the rows of the other tabs, and a tab shows its filter again when you come back. The tab row shows a `/` in the accent colour after the count of each other tab that has a filter. Enter on an issue with a session, and Enter on a PR, keep the filter of the tab you leave, and clear the filter of the tab you go to only when it hides the target row.
- `lists-saved-filters` reads `saved_filters` (a list of non-empty strings) from `config.json`. In the `/` prompt, Down puts the next saved filter in the prompt and Up the one before, with wrap. Text that is not a saved filter goes to the first (Down) or last (Up). The key bar shows `↑↓ to saved filters` only when the list is not empty.
- `lists-sort` cycles the order of the current tab with `S`, shown as `S sort: <order>` at the right end of the key bar. Rows are sorted inside each group.
- `lists-mouse` selects a row on a click. A double-click acts like Enter on the row: it opens the start dialog on an issue, goes to the issue of a PR, and attaches to a session. A click on the prompt opens the filter, and `esc to clear` at its right end clears a kept filter. The wheel moves the selection.
- `lists-hover` gives the clickable target under the pointer a dark grey background (`#3c3836`): a tab label (its number badge keeps its color), a row, a key bar hint, a menu row, a dialog label, mode option, or button. A text input gets no tint. The selection marker `❯` does not move. While an overlay is open, only the overlay and the footer show hover. Moving off every target, or the terminal losing focus, clears it.
- `lists-columns` gives the title column at least two fifths of the terminal width. When the summaries in the list are short (for example `author · labels` on the Issues tab), the title column grows into the free space, up to the longest title. Each group sizes its own columns, so a long Claude message in `Working` does not narrow the titles in `Open`. All summaries of a group start in one column. A work column on the Sessions tab takes its cells from a grown title column, so it never cuts a summary that fits. A title that does not fit ends in `…`. A title shows its inline Markdown as GitHub does: `` `code` `` is orange and `**bold**` is bold, without the marks. A title that is not one plain paragraph (`1. x`, `# x`, `- x`, or HTML) shows as written. The age stays right-aligned. Each group heading starts in the same column as the row icons. To see it, run `$V tmux "$RUN" resize-window -t drive -x 90 -y 30`, then switch tabs and compare with the 160-column screen.
- `lists-number-links` makes the `#N` of each row a terminal hyperlink (OSC 8) to its page on GitHub: an issue to `…/issues/N`, a PR to `…/pull/N`, and a session (`#N` or `PR #P`) to its issue or PR. The URL is the `url` that `gh issue list` and `gh pr list` return. The cells, colors, and width of the row do not change, and a terminal without OSC 8 shows plain text. A session whose issue or PR is not in the list has no link.
- `lists-pr-icon` shows the state of the lead PR of each issue in the glyph column before `#N`, and `PR #P open · <checks>` in the row summary.

## How to get to it (user POV)

- Start dispatch in a checkout. The Issues tab opens.
- Press `1`, `2`, or `3`, or click a tab name.

## Driving it with verify.sh

Preconditions:

- A run is up and doctor shows no `FAIL`.

- **Tabs.** Press `2`. Run `$V keys "$RUN" 2`, `$V wait "$RUN" 'enter to go to issue'`, and `$V wait "$RUN" 'updated [0-9]+[smh]? ago'`. The key bar shows `enter to go to issue` only on the PR tab. Line 2 shows ` 2  Pull requests N`. Run `$V shot "$RUN" prs-tab`.
- **Freshness.** Run `$V screen "$RUN" | sed -n 5p`. It shows `<repo> · updated Ns ago` next to the logo. On tab 3 the line shows only `<repo>`.
- **Refresh.** Press `r`. Run `$V keys "$RUN" r` and `$V wait "$RUN" 'refreshing…|updated [0-9]s ago'`. `gh-calls.log` gets two new `gh issue list` lines (the issues, then their links with `url,closedByPullRequestsReferences`) and one `gh pr list` line, and can get a `gh api graphql` line for older linked PRs.
- **Filter.** On the PR tab, press `/` and type a word from one title. Run `$V keys "$RUN" /` and `$V wait "$RUN" 'enter to keep · tab to complete · esc to clear'`, then `$V type "$RUN" '<word>'`, `$V keys "$RUN" Enter`, and `$V wait "$RUN" '❯ /<word>'` (the prompt line shows the kept filter). Only matching rows stay. Text that matches nothing shows `No pull requests match the filter.` Press Esc, `$V wait "$RUN" '/ to filter pull requests'`, and all rows come back.
- **Per-tab filter.** On tab 1, press `/`, type a word from one issue title, and press Enter. Press `2`. Run `$V wait "$RUN" '/ to filter pull requests'`: the PR tab has no filter, and all PRs show. Run `$V screen "$RUN" | sed -n 2p`: it shows `Issues N /`. Press `1` and `$V wait "$RUN" '❯ /<word>'`: the issue filter is back. Press Esc to clear it.
- **Saved filters.** Add `"saved_filters": ["label:<name>", "<word>"]` to `$RUN/xdg/dispatch/config.json` (keep the other fields), then run `$V restart "$RUN"`. Press `/` and `$V wait "$RUN" '↑↓ to saved filters'`. Press `Down` and `$V wait "$RUN" '❯ label:<name>'`. Press `Down` again for `<word>`, and `Down` once more goes back to `label:<name>`. `Up` goes the other way. Press Enter: only the matching rows stay.
- **Filter terms.** On the Issues tab, check first which labels and milestones the open issues have: `gh issue list -R <repo> --json number,labels,milestone`. Press `/`, run `$V type "$RUN" 'label:<name>'`, press Enter, and `$V wait "$RUN" '❯ /label:'`. Only the issues with that label stay. Run `$V shot "$RUN" label` and `grep -o $'\e\[[0-9;]*mlabel:<name>' "$RUN"/evidence/*label.ansi`: the term has the accent colour `38;2;131;165;152`. Add a word after the term to narrow it more. For a milestone with spaces, type `milestone:"<title>"`. Press `/` again and Backspace the term away. Type `-label:<name>`: the issues with that label go and the others stay, and the whole term, with its `-`, has the accent colour. Type `state:bogus`: the list is empty and the term is red (`38;2;251;73;52`). Clear the filter, then type `has:pr` and the issues with a PR stay. `gh-blocked.log` stays empty: the login query at start is a read.
- **Filter completion.** Press `/`, run `$V type "$RUN" 'la'`, and `$V keys "$RUN" Tab`. The prompt in the filter input shows `❯ label:` (the kept filter shows `❯ /label:`). `label:` is the only key that starts with `la`, so the next Tab goes on to the values: the prompt shows the first label of the tab in sort order, for example `label:bug`. Press Tab again for the next label, and Shift-Tab (`BTab`) goes back. A label with spaces shows in quotes. Type any letter: the next Tab starts again from what you typed. `$V wait "$RUN" 'tab to complete'` finds the new key hint in the filter footer. `gh-calls.log` gets no new line from Tab.
- **Sort.** Press `S` on the PR tab. Run `$V keys "$RUN" S` and `$V wait "$RUN" 'S sort: newest'`. Each press moves to the next order: `attention`, `newest`, `oldest`, `recently updated`, `number`, then `attention` again. The Issues tab adds `most comments` after `number`. The Sessions tab has only `attention` and `number`. The selected row stays selected.
- **PR icon.** On the Issues tab, an issue with an open PR shows `●` before `#N`, for example `❯ ● #12 … PR #17 open · ✗ checks failing`. A draft PR shows `◌` and a merged PR shows `✓`. An issue with no PR, or a closed one, shows `·`. A session glyph (`▲`, `●`, `○`, a purple `✓` when merged, an aqua `…` while it starts) takes the place of the PR mark, and so does the mark `◆` of an issue marked with Space. The color of `●` follows the checks: green pass, red fail, yellow pending, plain with no checks.
- **Number links.** On each tab, run `$V shot "$RUN" links`, then `grep -o $'\e]8;;https[^\e]*' "$RUN"/evidence/*links.ansi`. tmux keeps the links in its cells, and `capture-pane -e` writes them back. There is one `]8;;https://github.com/<repo>/issues/N` line (tab 1 and 3) or `/pull/N` line (tab 2) for each row on the screen, and each one is followed by an empty `]8;;` that closes it. The text between them is only the `#N` (or `PR #P`) of the row. Press `j` and shoot again: the links stay. The `.txt` shot is the same as without links.
- **Hover.** Mouse motion is an SGR sequence with button code 35. Run `$V tmux "$RUN" send-keys -t drive:dispatch -l $'\e[<35;X;YM'`. Coordinates are 1-based. Use `$V screen "$RUN" | grep -n` and `awk '{print index($0,"<text>")}'` to get Y and X. Then run `$V tmux "$RUN" capture-pane -e -p -t drive:dispatch | grep -n '48;2;60;56;54'`. Only the line of the hovered target prints. Move to `1;1` and nothing prints. In the settings menu, point at `detect_waiting`, not `icons`, because `icons` can also match a title under the overlay.
- **Fetch failure.** Not driven by default. To see it, copy `$RUN/bin/gh`, make `gh issue list` exit 1 in it, press `r` on tab 1, then restore the copy. The header shows `refresh failed Ns ago` in yellow, the message row shows `gh failed, showing old data: …`, and the old rows stay. When no rows were loaded before, the message row shows `gh failed: …` and the list is empty.

## Gotchas

- The counts and rows are live GitHub data. Do not assert fixed numbers.
- `up` is ready when the Issues fetch finishes. The PR fetch is separate and can still be running. On tab 2, wait for `updated` before you read the rows.
- If tab 2 shows `No pull requests.` and the message row shows `gh failed: gh failed with code 1: HTTP 502` (or `504`), the repo has too many PRs for dispatch's PR query. GitHub is not down. Use a smaller repo (see [README.md](README.md)).
- The Sessions tab shows no fetch age. Do not wait for `updated` there.
- On PR rows `✓` means checks pass, not merged. A PR in `Ready for review` with `✓` is open. Read the group heading.
- Mouse input is not driven by `verify.sh`. To test a click, send an SGR mouse sequence with `$V tmux "$RUN" send-keys -t <pane> -l $'\e[<0;X;YM'` and the release `m`. Coordinates are 1-based.
- The `.ansi` shots keep the colors. Use them when a claim depends on color, for example a green or red PR icon, or which tab is selected.
