# Sessions

The Sessions tab lists each session that dispatch started, with its state. From any tab a user can attach to a session, stop it, or resume an exited one. dispatch keeps no state file: it reads sessions from git and tmux each time. A session belongs to an issue (`#N`) or to a PR (`PR #P`). The keys work the same on both, and each toast names the session by its key, for example `Stopped PR #P.`.

## Sub-features

- `sessions-state` shows the row glyph `●` (running), `▲` (needs you), or `○` (exited). The row has only the glyph, not the word. The words are in the group headings (`Needs you N`, `Working N`, `Exited N`) and in the counts on header line 6: `▲ N needs you   ● N working   ○ N exited   ✓ N merged`. A session whose branch has a merged PR shows a purple `✓`, in a `Merged` group after `Exited`, whatever its window does.
- `sessions-attach` moves the tmux client to the session window with `a` on any tab, or Enter on the Sessions tab.
- `sessions-stop` kills the window with `x` on a live session. The worktree and the branch stay. On an exited session, `x` shows `No running session here.`
- `sessions-message` sends one line to a live session with `t`, with no attach. The prompt row shows `❯ message to #N: <text>▏` and the key bar `enter to send · esc to cancel`. Enter types the line into the session window and presses Enter, then shows `Sending to #N…` and `Sent your message to #N.`. A failed send shows `Sending the message to #N failed: <error>.` in red. Enter on a blank line shows `Type a message first.` and keeps the field open. Esc closes it and sends nothing. On a row with no live session, `t` shows `No running session here.` The key bar shows `t to send message` only for a live session.
- `sessions-resume` runs the resume command of the session's harness in the worktree (`claude --continue`, `codex resume --last`, `opencode --continue`, `agy --continue`) with `a` (or Enter on the Sessions tab) on an exited session. The key bar shows `a to resume`. A missing window (after `x`) gets a new `#N` window. A dead pane (after the agent exits) is respawned in the same window.
- `sessions-resume-fresh`: `a` on an exited Claude session whose worktree has no Claude transcript opens the start dialog for its issue, with the toast `#N has no conversation to continue. Start it again.` `claude --continue` would exit at once there. This happens after a start whose Claude never ran.
- `sessions-remove` removes the worktree and the branch with `D` twice, on an exited session or one whose PR is merged, then runs `git worktree prune`. It refuses a worktree with uncommitted changes or a branch with commits that no remote has. For a squash- or rebase-merged PR whose remote branch was deleted, it still removes a clean worktree on the session branch with no local commits beyond the PR's `head_oid`. Uncommitted changes, extra local commits beyond `head_oid`, or another checked-out branch with unpushed commits are still refused. It closes the window if one exists.
- `sessions-clean` removes all clean merged sessions when you press `c` twice. The key bar shows `c to clean merged` only on the Sessions tab when at least one merged session is listed. It skips dirty or unpushed sessions and per-session errors without aborting the batch, runs `git worktree prune` once, and reports removed, skipped, and failed counts in one toast.
- `sessions-summary` shows, in the row summary, the newest recap (after `※`) or assistant text in the worktree's newest transcript, joined into one line and cut to fit. The row shows it as Markdown without the syntax: `**bold**` is bold, `` `code` `` is orange, and block marks (`#`, `-`, `>`, fences) are dropped. `i` opens a box titled ` #N recap ` or ` #N last message ` with the full text as styled Markdown, word-wrapped: headings are bold, lists keep their bullets and hanging indent, quotes have a `│` gutter, code blocks and tables fit the box, and no raw `**` or `` ` `` shows. `j`/`k` and the wheel scroll it, and `i` or `Esc` closes it. The key bar shows `i to read summary` only when the session has a summary. With no session, `i` shows `No session for this issue. Press s to start one.`, and with no summary `Claude has not said anything in #N yet.` dispatch reads a transcript again only when its size or mtime changed.
- `sessions-pr` lists a PR session as `PR #P <PR title>`, with the summary `PR #P open` until Claude says something. Its window is `PR #P` and its worktree `.claude/worktrees/pr-P`. `a`, `x`, `t`, `i`, `d`, `!`, `D`, `m`, and `o` work on it. The toasts use the key: `message to PR #P: <text>`, `Sent your message to PR #P.`, `Claude has not said anything in PR #P yet.`, ` PR #P last message `, `PR #P is still running. Press x to stop it first.`, `Stopped PR #P.`, `Press D again to remove PR #P's worktree and branch.`, and `Removed PR #P's worktree and branch.`, ` PR #P diff `, and the shell window `PR #P shell`. `o` opens the PR, not an issue.
- `sessions-diff` shows the worktree diff with `d` on any row that has a session, in a box titled ` #N diff ` with `Reading the diff…` until git answers. The box lists each untracked file as `untracked: <path>`, then the patch of `git diff --merge-base <origin/base> --stat --patch` (commits ahead plus uncommitted tracked changes). `+` lines are green, `-` lines red, `@@` lines blue, and file headers bold. Long lines are cut with `…`, not wrapped. `j`/`k` and the wheel scroll it, and `d` or `Esc` closes it. With no session, `d` shows `No session for this issue. Press s to start one.` With no changes it shows `#N has no changes.` A git failure shows `Reading the diff of #N failed: <error>.` in red. The key bar shows `d to show diff` only when the session has commits ahead or uncommitted changes.
- `sessions-shell` opens a plain shell in the session's worktree with `!`, in a new tmux window named `#N shell` that has no dispatch tag, so the list never shows it as the session. The window turns `remain-on-exit` off, so it closes when the shell exits, also when tmux sets `remain-on-exit` globally (the sandbox does). It works for an exited session. It does not touch Claude's window. With no session, `!` shows `No session for this issue. Press s to start one.` A failure shows `Opening a shell in #N failed: <error>.` in red. The key bar shows `! to open shell` only when the row has a session.
- `sessions-derived` lists the same sessions after dispatch restarts.
- `sessions-work` shows the state of each session's work in its own column, right-aligned before the age, with only what needs action: `±N` (yellow) for the paths `git status` lists, `↑N` (yellow) for commits that the remote copy does not have (all the commits ahead of the default branch when `origin` has no such branch), and `↓N` (yellow) for commits on the remote copy that the branch does not have. The remote copy is `origin/<branch>`, or for a fork session (`fork/pr-P`) the branch of its fork remote `dispatch-fork-pr-P`. A green `✓` shows when the remote copy is at the branch's commit, the branch has commits, and nothing is uncommitted. A session with no commits and no changes shows nothing. The Nerd Font set draws `` `` `` ``. The summary (the last Claude message or the PR) is not changed. The poll reads it every 2 s with git only, so it shows within one poll after a change.
- `sessions-other-branch` keeps a session on the list when its worktree has another branch or a detached `HEAD` checked out. The row summary shows `on <branch>, not <session branch>` (or `on detached HEAD, not …`) in yellow, in place of what Claude said and the PR. `D` still deletes the session branch, and the other branch stays.

## How to get to it (user POV)

- Press `3` for the Sessions tab.
- A PR session is on the Sessions tab only. The Pull requests tab shows the PR row, and `s` there goes to its session.
- On the Issues tab, a row with a session shows its state as the glyph before `#N`, in the `Needs you` or `Working` group. `a` and `x` work there too.
- Press `a` on a session to attach, or Enter on the Sessions tab. Press `x` to stop. Press `t` to send a message without attaching. On the Issues tab, Enter on an issue with a session only goes to the Sessions tab.

## Driving it with verify.sh

Preconditions:

- A run is up and doctor shows no `FAIL`.
- A session for issue `#N` exists. Make it with [Start a session](./start-session.md).

- **State.** Press `3`. Run `$V keys "$RUN" 3` and `$V wait "$RUN" '▲ 1 needs you'`. The row shows `▲ #N`. The key bar shows `a to attach · x to stop` (with no `enter`), and the prompt shows `/ to filter sessions · a to attach`. Run `$V shot "$RUN" sessions-tab`.
- **Input.** Type a line into the session window, as a user does after attach. Run `$V tmux "$RUN" send-keys -t '#N' 'hello' Enter`. `claude-calls.log` gets `hook UserPromptSubmit`, `got: hello`, and `hook Stop`. Do not wait for `● 1 working` here: the fake claude is busy for 1 s, and dispatch reads the state every 2 s, so it often never shows. See **Resume** for a reliable `● 1 working`.
- **Message.** Select the live `#N` session. Press `t`, then `$V type "$RUN" 'yes, go with plan B'` and `$V wait "$RUN" 'message to #N: yes, go with plan B'`. The key bar is `enter to send · esc to cancel`. Run `$V shot "$RUN" message-field`. Press Enter and `$V wait "$RUN" 'Sent your message to #N'`. `claude-calls.log` gets `got: yes, go with plan B`, and `$V window "$RUN" '#N'` shows `FAKE-CLAUDE got: yes, go with plan B`. Press `t` then Enter: the toast is `Type a message first.` Type `drop me` and press Escape: the prompt row shows the filter hint again, and `claude-calls.log` has no `got: drop me`. On an exited session, `t` shows `No running session here.`
- **Attach.** Attach a client, then press `a`. Run `$V client "$RUN"`, `$V tmux "$RUN" select-window -t drive:dispatch`, `$V keys "$RUN" a`, and `$V tmux "$RUN" display -p -t drive '#{window_name}'`. It prints `#N`. Go back with `$V tmux "$RUN" select-window -t drive:dispatch`.
- **Diff.** Needs session `#N`. Run `W=$RUN/work/<repo>/.claude/worktrees/N`. With a clean worktree, the key bar hides `d to show diff` (and keeps `! to open shell`), and pressing `d` shows `#N has no changes.` Write `echo x > $W/new.txt` and run `echo '# edit' >> $W/<a tracked file>`. Within one poll the key bar shows `d to show diff`. Run `$V keys "$RUN" d` and `$V wait "$RUN" ' #N diff '`. The box shows `untracked: new.txt`, `diff --git`, and a green `+# edit`. Run `$V shot "$RUN" diff`. Press `j` and `k`: it scrolls only when the diff is longer than the box. Press `d` or `Escape`: the box closes. `d` with no session selected shows `No session for this issue. Press s to start one.`
- **Shell.** Attach a client first: `$V client "$RUN"` and `$V tmux "$RUN" select-window -t drive:dispatch`. Press `!`. Run `$V keys "$RUN" '!'`, then `$V tmux "$RUN" list-windows -a -F '#{window_name} #{pane_current_path}'`: it shows a `#N shell` window with the worktree as its path, next to the `#N` window. Run `$V tmux "$RUN" display -p -t drive '#{window_name}'`: it prints `#N shell`. Go back with `$V tmux "$RUN" select-window -t drive:dispatch`. The `#N` row keeps its state, and the header counts do not change. Type `exit` into the shell window (`$V tmux "$RUN" send-keys -t '#N shell' exit Enter`): the window closes. On an exited session, `!` still opens the shell.
- **Stop.** Press `x`. Run `$V keys "$RUN" x` and `$V wait "$RUN" 'Stopped #N'` (`Stopping #N…` comes first). The row shows `○ #N`, the header `○ 1 exited`, the key bar `a to resume`, and the prompt `/ to filter sessions · a to resume`. `x` again shows `No running session here.` `$V state "$RUN" after-stop` shows the worktree and the marker, and no `#N` window.
- **Resume.** Press `a` on the exited session. Run `$V keys "$RUN" a` and `$V wait "$RUN" 'Resumed #N\. Press a to attach\.'` (`Resuming #N with claude --continue…` comes first. A session started with another harness shows its own command, for example `Resuming #N with codex resume --last…`, and a resume of it never starts the start dialog, because only Claude has a transcript. A resume uses the harness in `branch.<b>.dispatch-harness`, not the one in the config). Then `$V wait "$RUN" '● 1 working' 3` (the row shows `● #N` under `Working 1`): dispatch reads the state at once after a resume, and the fake claude types a line and is busy for 2 s at start. Then the header shows `▲ 1 needs you`. `claude-calls.log` has a new line whose argv starts with `--continue --settings`. `$V state` shows a new `#N` window id with the worktree tag.
- **Exit.** Type `exit` into the session window. Run `$V tmux "$RUN" send-keys -t '#N' exit Enter`. The row shows `○ #N` and the header `○ 1 exited`. `$V state` shows the `#N` window with `dead=1` (remain-on-exit).
- **Resume a dead pane.** Press Enter on the exited session (Sessions tab). Run `$V keys "$RUN" Enter` and `$V wait "$RUN" 'Resumed #N'`. `$V state` shows the same window id as after **Exit**, now with `dead=0`.
- **Resume with no conversation.** The fake claude saves a transcript under `$RUN/claude/projects/` on each start without `--continue`, as real Claude does on its first prompt. Stop the session with `x`, then delete it with `rm "$RUN"/claude/projects/*-N/fake.jsonl`, and wait 3 s for dispatch to read the sessions again. Press `a`. Run `$V wait "$RUN" 'Start session for #N'` and `$V wait "$RUN" '#N has no conversation to continue. Start it again.'`. Run `$V shot "$RUN" resume-fresh`. Ctrl-S starts the session in the same worktree. `claude-calls.log` gets a line whose argv ends with the issue prompt, not `--continue`.
- **Remove.** Needs an exited session whose branch has no commits of its own. The key bar of a running session has no `D to remove`. Press `D` on it: the toast says `#N is still running. Press x to stop it first.` Type `exit` into the session window and wait for `○ 1 exited`. The key bar shows `D to remove`. Make the worktree dirty: write a file in it with `echo x > "$RUN/work/<repo>/.claude/worktrees/N/dirty.txt"`. Run `$V keys "$RUN" D`, then `$V wait "$RUN" 'Press D again to remove #N'`, then `$V keys "$RUN" D`. Run `$V wait "$RUN" '#N has changes that are not committed'`. `$V state` still shows the worktree. Delete `dirty.txt`. Press `D` twice again and run `$V wait "$RUN" "Removed #N's worktree and branch"`. `$V state "$RUN" after-remove` shows no worktree for `#N`, no marker, and no `#N` window. The directory is gone and `git -C "$RUN/work/<repo>" branch` does not list the branch. For the unpushed refusal, make a commit in the worktree before the exit (`git -C <worktree> commit --allow-empty -m wip`): the toast says `#N has 1 commit that is not pushed. Push it, then press D again.` Do not push in the sandbox. Press `D` and any other key between the presses: the removal does not run.
- **Squash-merged remove.** Needs a session `#N` whose PR is `MERGED`, whose remote branch `origin/<branch>` is absent, and whose worktree `$W` is on `<branch>` at the PR's `head_oid` (for example, fetched via `git fetch origin refs/pull/<P>/head` and reset to `FETCH_HEAD`). Make an extra local commit in `$W` with `git -C "$W" -c user.name=t -c user.email=t@t commit --allow-empty -m extra`. Press `D` twice: the toast says `#N has 1 commit that is not pushed. Push it, then press D again.` Reset back to the PR head with `git -C "$W" reset --hard HEAD~1`. Press `D` twice and run `$V wait "$RUN" "Removed #N's worktree and branch"`. `$V state "$RUN" after-squash-remove` shows no worktree for `#N`, no marker, no `#N` window, and no `prunable` worktree entries (`git -C "$RUN/work/<repo>" worktree list` lists no deleted path).
- **Bulk clean.** Needs at least two sessions on the Sessions tab with merged PRs: `#N` clean and `#M` dirty (`echo x > "$RUN/work/<repo>/.claude/worktrees/M/dirty.txt"`). Press `3`. The key bar shows `c to clean merged`. Run `$V keys "$RUN" c` and `$V wait "$RUN" 'Press c again to remove 2 merged sessions'`. Run `$V keys "$RUN" c` and `$V wait "$RUN" 'Removed 1 merged session\. Skipped 1: #M \(uncommitted changes\)\.'`. `$V state "$RUN" after-clean` shows `#N` removed, `#M` still present with `dirty.txt`, and no stale `prunable` worktree metadata. Press `c` once and any other key between the presses: no session is removed.
- **Summary.** Press `3` and select `#N`. Press `i`: the toast says `Claude has not said anything in #N yet.` (the fake transcript has only a user line). Write an assistant line as Claude does: `T=$(ls "$RUN"/claude/projects/*-N/fake.jsonl)`, then `printf '%s\n' '{"type":"assistant","message":{"content":[{"type":"text","text":"First line of the answer.\n\nSecond paragraph."}]}}' >>"$T"`. Run `$V wait "$RUN" 'First line of the answer\. Second paragraph\.'` (within 3 s): the row joins both paragraphs on one line. The key bar shows `i to read summary`. Then append a second assistant line with Markdown: `printf '%s\n' '{"type":"assistant","message":{"content":[{"type":"text","text":"## Done\n\nFixed **the queue** with `retry`.\n\n- first\n- second"}]}}' >>"$T"` and `$V wait "$RUN" 'Done Fixed the queue with retry\. first second'`: the row shows no `**`, `` ` ``, or `##`. Press `i`, then `$V wait "$RUN" ' #N last message '`. The box shows the paragraphs of the newest message on separate lines, bold and orange where marked, with `• first` and `• second` as a list, and no raw `**`, `` ` ``, or `##`, and the bar `j/k to scroll · esc to close`. Run `$V shot "$RUN" summary`. Press `Escape`. Append a recap: `printf '%s\n' '{"type":"system","subtype":"away_summary","content":"You fixed the queue. (disable recaps in /config)"}' >>"$T"` and wait for `※ You fixed the queue.` Press `i`: the title is ` #N recap ` and the note `disable recaps` is not on screen. Press `i` to close it.
- **Other branch.** Switch the worktree branch by hand, as a user does in the session. Run `git -C "$RUN/work/<repo>/.claude/worktrees/N" switch -c try-other` and `$V wait "$RUN" 'on try-other, not <branch>'`. The `#N` row is still listed with the same state. Run `$V shot "$RUN" other-branch`. Run `git -C … switch --detach` and wait for `on detached HEAD, not <branch>`. Switch back to `<branch>`: the summary shows `<branch>` again. With `try-other` checked out, **Remove** deletes `<branch>` and the worktree, and `git -C "$RUN/work/<repo>" branch` still lists `try-other`.
- **Work state.** Needs a session `#N` on its own branch `<branch>`. Press `3`; the row has no work column and the summary is unchanged. Run `W=$RUN/work/<repo>/.claude/worktrees/N`. Write two files with `echo x > $W/a.txt; echo y > $W/b.txt` and run `$V wait "$RUN" '±2'`. Commit one with `git -C $W add a.txt && git -C $W -c user.name=t -c user.email=t@t commit -m wip` and wait for `±1 ↑1`. Do not push in the sandbox: stand in for a push with `git -C $W update-ref refs/remotes/origin/<branch> HEAD` and wait for a `±1` with no `↑`. Delete `b.txt` and wait for the green `✓`. Commit a new file the same way and wait for `↑1`. Run `$V shot "$RUN" work-state` after each step.
- **PR session.** Start one with **PR session** in [Start a session](./start-session.md). Press `3`. The row is `❯ ▲ PR #P <title>  PR #P open`, and the key bar shows `? to keys · a to attach · x to stop · t to send message` (plus `d to show diff` when the branch has changes, `! to open shell`, `m to merge`, `o to open on GitHub`, and `q to quit`), with no `enter to attach`. Run `$V shot "$RUN" pr-session-row`. Then:
  - Press `t`, type `hello pr`, and wait for `message to PR #P: hello pr`. Press Enter and wait for `Sent your message to PR #P.`. `claude-calls.log` gets `got: hello pr`. Read the window with `$V window "$RUN" 'PR #P'`: it shows `FAKE-CLAUDE got: hello pr`.
  - Press `i`: the toast is `Claude has not said anything in PR #P yet.` Append an assistant line to `$RUN/claude/projects/*pr-P/fake.jsonl` as in **Summary**, wait for the row summary, press `i`, and wait for ` PR #P last message `.
  - Press `o` and wait for `Opening PR #P on GitHub…`. `browser.log` gets `…/pull/P`.
  - Run `$V client "$RUN"`, select `drive:dispatch`, press `a`. `$V tmux "$RUN" display -p -t drive '#{window_name}'` prints `PR #P`. Select `drive:dispatch` again.
  - Press `D`: the toast is `PR #P is still running. Press x to stop it first.` Press `x` and wait for `Stopped PR #P.`. The row shows `○ PR #P` and the key bar `a to resume · i to read summary · D to remove`.
  - Press `D` and wait for `Press D again to remove PR #P's worktree and branch.`. Press `D` and wait for `Removed PR #P's worktree and branch.`. `$V state "$RUN" pr-after-remove` shows only the main worktree and no `PR #P` window. It prints `(none)` under markers, and `git branch` lists only the default branch.
- **Restart.** Quit and start dispatch again in the same run. Run `$V keys "$RUN" q`, then `$V restart "$RUN"` (it waits for `updated`). Press `1` and run `$V doctor "$RUN"`: it must show `ok` for `TMUX on this run's socket`. Press `3`. The `#N` session is still listed with the same state. If a live session shows `○` after a restart, dispatch lost `TMUX` and reads the wrong tmux server.

## Gotchas

- `a` without an attached client fails with `Attaching to #N failed: tmux failed with code 1: no current client.`. dispatch runs `select-window ; switch-client`, and the switch needs a client. Run `$V client "$RUN"` first.
- After `a`, the active tmux window is `#N`. `$V keys` and `$V screen` still reach dispatch by pane id. Select `drive:dispatch` again before you check what a user sees.
- `x`, `a`, `t` and `D` act on the selected row. `c` acts on all merged sessions and re-arms if the set of merged sessions changes between the two presses. `t` keeps the issue it opened on, so the message goes there even if the selection moves. On the Issues tab, select the issue row first.
- The `needs you` state needs `detect_waiting` (on by default) and the tmux backend. If the window tag shows `waiting=` empty after the fake claude prints `waiting for input`, the hooks did not run: read `claude-calls.log`.
- A PR session window is `PR #P`, with a space. Quote it: `$V window "$RUN" 'PR #P'`, and `send-keys -t 'drive:=PR #P'`.
- `restart` in **Restart** uses tmux, not a user key. It stands in for the user who starts dispatch again. Do not use `$V tmux "$RUN" respawn-pane` for this: tmux gives the pane the `PATH` of your shell, so dispatch runs the real `gh` with no guard, and it can get herdr or herdr app variables. Doctor then fails on `gh guard first on PATH` or on the variables check.

## Other harnesses

`verify.sh up` puts stand-ins named `codex`, `opencode`, and `agy` on the sandbox `PATH`. They are one script (`fake-agent`) that logs `agent=<name> argv: ...` to `claude-calls.log`, takes no hooks, and echoes input. The config has `command` set to `fake-claude`, which only applies to the `claude` harness.

- **Start and resume with Codex.** Press `,`, then `j` three times to `harness`, and Enter: the row shows `harness   codex` and the file is `{"detect_waiting":true,"multiplexer":"tmux","harness":"codex"}` (the `command` override is gone). Start a session (see start-session.md). `$V state` shows `branch.<b>.dispatch-harness codex`, and `claude-calls.log` has `agent=codex argv: ...`. Stop it with `x`, and change `harness` in the menu again. Press `a`. The toast is `Resuming #N with codex resume --last…`, and the log has `agent=codex argv: resume --last`. The toast lasts less than a second with the stand-in, so poll for it with a loop around `$V tmux "$RUN" capture-pane -p -t drive:dispatch`.
- **Summary.** Press `i` on a running Codex session: the toast is `Codex does not report what it said.`
- Herdr and the herdr app are not covered here. The sandbox has no herdr.
